## Context

The trial ran `opencode run --standalone --agent plan` with the owner's configured model. The `plan` agent denies editing, but it allows every shell command, so read-only rested on the prompt and the snapshot alone.

## Decisions

- **A dedicated `reviewer` agent in the user's OpenCode configuration.** It denies every action by default. It allows reading, search, globbing, and web fetch and search. It allows shell commands only from a read-only allowlist: `git diff`, `log`, `show`, `status`, `ls-files`, `rev-parse`, `blame`, and `merge-base`, each matched as the exact subcommand or the subcommand followed by a space, so `git difftool` and `git show-ref` do not match; and `cat`, `grep`, `rg`, `ls`, `wc`, `head`, `tail`, `diff`, `shasum`, and `pwd`. `sed` and `git grep` are left out, because `sed` can write with its `w` command and `git grep -O` opens a pager. Later rules deny commands that can write or run programs through an allowed prefix: output redirection, command substitution, `tee`, `xargs`, `sed -i`, `--output`, `-exec`, `--pre ` and `--pre=`, process substitution, `--ext-diff`, `--textconv`, `difftool`, `--no-index`, and arguments that are absolute paths, start with `~`, or go up with `..`. The agent denies `external_directory`, which covers its read tool; shell reads outside the worktree are limited only by the pattern rules, which deny absolute paths, `~`, `..`, `$`, and input redirection. OpenCode applies the last matching rule, so every deny rule follows the last allow rule. A probe confirmed the denials: redirection, `--output=`, `tee`, `sed -i`, and a chained `touch` were all denied, and allowed reads ran. The snapshot check remains the proof of a read-only pass, because a pattern allowlist is not a sandbox.
- **`< /dev/null`.** When stdin is not a terminal, `opencode run` waits for the end of stdin before it submits the prompt. The coordinator's shell left stdin open, so most runs hung with no output, and the OpenCode database held no message for them. With `< /dev/null`, five pings in a row succeeded in 4–6 seconds. The provider also stalled single steps for 38 and 162 seconds, so the invocation allows at least 30 minutes.
- **Model `opencode/kimi-k3`.** The owner chose it at about 14:40 local time, after the trial and before the root cause was found. It uses its default variant, which the stored assistant messages record.
- **`--standalone`.** It is chosen for isolation. Without it, `opencode run` attaches to the background service, which runs in another directory. The trial's first stall without it is explained by the open stdin, not by the service.
- **The model is set in the invocation.** `-m opencode/kimi-k3` sets the model. The JSON events do not name it, but OpenCode's stored assistant message records the model and its variant.
- **Rotation order follows the list order:** Codex, Antigravity, OpenCode, Claude Code, then back to Codex. It skips reviewers that are paused, unavailable, or unable to meet the review requirements, unless a change needs a particular reviewer.
- **Derived mechanics are attributed to the coordinator.** The owner's rule is quoted as the owner's. The mechanics that apply it to the existing rules are marked as the coordinator's.
- **Findings on the archived change's record are not fixed here.** Three of the trial's Low findings concern the archived `verification.md` of `add-reviewer-unavailability-rule`: L3, a missing Limitations section; L4, an unrecorded edit after pass 3; and L7, a model confirmation in pass 3. This change records them in its own `verification.md` and leaves the archive unchanged.

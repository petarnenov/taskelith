## Context

Item 3 evaluated the contract tooling (`docs/contract-tooling.md`) and proposed, for document-first schemas, `@asyncapi/parser` for AsyncAPI validation, `openapi-typescript` and `json-schema-to-typescript` for types, ajv for validation, and oasdiff and `@asyncapi/diff` for breaking changes. Item 8 installed ajv. Item 7 defined admission records, and item 5 gates and evidence; those are the first payloads. OpenAPI 3.1 schemas are JSON Schema 2020-12; AsyncAPI 3 schemas are draft-07.

## Goals / Non-Goals

Goals: the first two contract documents, types and validators generated from them, and a breaking-change gate in `make verify`. Non-goals: transport, servers and subjects, authentication, persistence, generated clients, linting, and running services.

## Decisions

- **Package and documents.** `packages/contracts` holds `documents/sdlc.openapi.json` and `documents/sdlc.asyncapi.json`. The documents are JSON so that the build, oasdiff, and the tests read them without a YAML dependency. AsyncAPI is 3.0.0: the parser's 3.1.0 support and `@asyncapi/diff`'s are unverified.
- **Shared shapes.** Each document is self-contained, in its own dialect, and both name their shared shapes the same way (identifier, instant, digest, generation, display text, artifact revision, work item, task kind, admission state, admission). A test requires every schema that both documents define to be identical, and the shared schemas use only keywords with the same meaning in draft-07 and 2020-12. This keeps one meaning for each shape without cross-file references, which `--allow-external-refs=false` and the AsyncAPI tools would complicate; it trades a little duplication for that.
- **Envelopes.** A command is `{ metadata, payload }`. Its metadata has the command identifier and type, schema version, issue time, optional expiry, correlation and optional causation, project and task identity, and the SDLC run, stage, admission, and admission generation (the admission revision); attempt, worker, and ownership generation are optional until assignments exist (G2). An event is `{ metadata, payload }` whose metadata extends the kernel `EventMetadata` with the producer identity and a per-producer sequence, plus optional attempt and ownership generation; cross-producer ordering is not implied. Each event message fixes its `eventType` with `const`. Command payloads are open objects until specific commands are defined.
- **Events.** Admission events carry `{ runId, admission }` and gate events `{ runId, gate }`, the full record after the change, with the event type naming the transition. The run identifier travels with the event because admission and gate records do not hold it.
- **HTTP operations.** `POST /runs` creates a run from a client-chosen run identifier, project, and run binding; `POST /runs/{runId}/tasks` submits a task (client-chosen task identifier, kind, stage, optional work item, and the starting revisions of a planning task) and returns its admission; `GET /runs/{runId}/admissions/{admissionId}` reads one. Client-chosen identifiers make retries idempotent. Errors carry the kernel failure shape; an admission rejection is 422. Authentication is defined with enrollment in G2, so the document declares no security scheme yet.
- **Generation.** `scripts/generate-contracts.ts` runs first in the root `build` script. It validates the AsyncAPI document with `@asyncapi/parser`, failing on errors and warnings, generates HTTP types with `openapi-typescript` and message types with `json-schema-to-typescript` (one interface maps every message schema name to its type), and writes both documents' component schemas as standalone bundles whose references point at their own definitions. Everything goes to `packages/contracts/src/generated/`, which git ignores.
- **Validators.** `checkHttpSchema(name, input)` and `checkMessageSchema(name, input)` compile the bundles with ajv in strict mode, `Ajv2020` for HTTP and the draft-07 class for messages, and return the typed value or readable violations; the schema name is typed, so only schemas of the documents can be named. Standalone precompiled validators are not needed until a CSP-restricted client exists.
- **Breaking changes.** `make contract-compatibility` finds the merge base of `HEAD` with `origin/dev`, fetching the branch when absent and the full history when a shallow clone cannot reach the base. For each document present at the base, it compares the base text with the working tree: oasdiff `breaking` runs as its digest-pinned image with `--network none`, a read-only mount of the two files, and `--allow-external-refs=false`, and its ERR-level changes are breaking; `@asyncapi/diff` compares the parsed documents, and its breaking and unclassified changes are breaking, except the change of `info.version` itself, which `@asyncapi/diff` calls breaking although it declares changes rather than being one, and the parser's `x-parser-*` annotations; a key of a schema map such as `properties` named `x-parser-…` is part of the contract and still counts. A breaking change passes only when `info.version` declares it: a higher major version, or a higher minor version while the major version is 0. Versions must follow the full semantic versioning 2.0.0 grammar, so a malformed prerelease cannot declare a change. A document absent at the base skips the comparison but must still have a valid version.
- **Versions.** Both documents start at 0.1.0, as nothing consumes them yet.

## Risks / Trade-offs

- Treating unclassified AsyncAPI changes as breaking makes compatible additions inside payloads, such as an optional field, need a version change too. It errs toward declaring changes until a finer classification is configured.
- `make verify` needs Docker. CI's runner has it; a local clone without it fails the check instead of skipping it.
- `@asyncapi/parser` brings the Spectral packages and `@scarf/scarf`; installs use `--ignore-scripts`, so its analytics install script does not run. The network behaviour of the generators is not measured.
- The wire schemas check shape; the domain parsers stay the authority on meaning. For example, JSON Schema counts string length in code points, the domain in UTF-16 code units.

## Decisions

1. **Crash points.** `CrashPoints` accepts `^[A-Z][A-Za-z0-9]*(?:\.(?:before|after))?$` (`packages/testing/src/crash-points.ts:5`), so the lifecycle points are `WS1` to `WS10`, each with `.before` and `.after`, and the bare `WS8` while the reclaim program runs (the contract's "during"). Contract section 3 holds the table and what a crash test checks around them; the spec's "Crash-safe lifecycle" names them. No constant is added to the package: 16b adds the points with the code that reaches them, and the workspace package does not depend on `@taskelith/testing`.
2. **Snapshot format (Q1).** The snapshot is Taskelith's own tar, content type `application/x-tar`, never `git archive`, so `export-subst` and `export-ignore` do not apply and the bytes do not depend on the Git version. The rules (contract section 10, spec "Snapshot archive format"): files and links only, in byte order of the UTF-8 paths, ustar fields with modes `0644`, `0755`, or `0777`, owner, group, and time `0`, empty names, a pax header (`path`, `linkpath`, `size`) only where a ustar field cannot hold the value, and two zero blocks at the end. A gitlink is refused with `precondition-failed` and reason `gitlink-in-tree`. The rules are a pure domain function, `encodeHeadSnapshot`, so the double and the 16b adapter produce the same bytes, and unit tests check the archive with the system `tar`. Paths that are not valid UTF-8 are not settled here (follow-up for 16b).
3. **Credential transport (Q2).** The secret reaches Git only as `http.extraHeader` (an `Authorization: Basic` header of `x-access-token:<secret>`, the form of the GitHub plugin's installation tokens) in command-scope environment configuration (`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_VALUE_<n>`), never an argument, a file, or a credential helper; `credential.helper` is set empty and `GIT_TERMINAL_PROMPT=0`, and inherited `GIT_TRACE*` variables are dropped. Remotes are HTTPS without user information (`checkRemoteTransport`, reason `insecure-remote`, checked in `prepare` after the target's repository and before the credential); plain `http://127.0.0.1` only under the test policy `https-or-loopback-http`. The policy is a two-value type, not a boolean flag.
4. **Push "never forced" (Q3).** Contract section 8 defines it as "the remote task branch never moves to a commit that does not descend from the leased head". A lease alone does not ensure that: Git lets a push whose lease matches replace the branch with any commit. So the adapter checks ancestry before the push (`not-fast-forward`) and the lease catches a move after that check (`remote-moved`). The only options are `--atomic --force-with-lease=refs/heads/<branch>:<expected>` (`taskBranchPushOptions`), empty on a first push; never `--force`, `-f`, a bare lease, `--force-if-includes`, or a `+` refspec. Two new cases, remote-moved and not-fast-forward, check the outcomes and that a successful push started one push process with those options; three defective variants (no lease check, no ancestry check, a bare lease) show the cases catch a wrong adapter.
5. **Hand-off state.** `WorkspaceLifecycle.handedOff()` returns the listed attempts whose hand-off record exists, in the order of `list`, read from the records. A new case checks it before, during, after a restart, and after the reclaim; the defective variant that keeps the state in memory misses the hand-off after a restart.
6. **Reclaim containment.** `reclaim-<name>` (`reclaimContainmentName`, `RECLAIM_CONTAINMENT_PREFIX`) under the worker's containment parent, written durably into the hand-off record before the program starts. The scan for unrecorded processes skips a containment that a hand-off record names. After a restart the worker polls until the containment is empty, never kills it, and at a bound that 16d fixes reports the workspace for reconciliation. A failed or killed program leaves the workspace handed off with `reclaim-failed`, and the record keeps that outcome, so the program is never run again for that hand-off (new requirement "Failed reclaim program").
7. **Same-identity platforms (Q5).** On macOS the reclaim program runs as the worker identity without a containment, in its own process group, which the hand-off record names in place of a containment (new requirement "Reclaim program on one account").
8. **Pinned Git client.** New requirement "Pinned Git client": the explicit path from the worker's tool manifest and an exact `git --version` string gate (`checkGitClient`, reason `git-client-mismatch`), with the pin injected so a test can give another. `GIT_CLIENT_PINS`: Linux `/usr/bin/git` printing `git version 2.43.0`, from the package `git=1:2.43.0-1ubuntu7.4`, whose package revision the version string does not show, so the image build checks it (16d); macOS `/usr/bin/git` printing `git version 2.50.1 (Apple Git-155)` (`docs/g3-dependencies.md` section 4). The tool manifest and the images come in 16d and 16e.
9. **Slots (Q4).** A Linux worker with a separate execution account has one slot and refuses to start with `TASKELITH_WORKER_SLOTS` above `1`, naming the variable and the account (contract section 3, new requirement "Single slot with a shared execution account" in `git-workspace-port`). `capacity-reservation` and `worker-runtime` are not changed; 16e implements it in the worker settings.
10. **Sections 13 and 14 (Q7).** Only the delegated-child half of the "One handed-off workspace" test moves to item 38 (contract sections 13 and 14, item 38 row). The worker half stays with item 16: its Linux tests in 16d and its admission in 16e. The item 16 row names 16a to 16e; nothing is reordered.
11. **Fixture hooks for 16d.** `gitProcesses()` returns each Git process the adapter started with its arguments, its process identifier, and the names of its environment variables, never their values, so a secret cannot leak through the observation; `plantGitSetting` and `gitConfig` plant and read `.git/config`. Two new cases use them: the built environment with no secret in an argument, and planted settings that never act. The double records the processes a real adapter would start and writes `.git/config` anew before each Git call.
12. **Native macOS conformance (Q10).** The existing gate tables (`docs/worker-platforms.md` "Native acceptance gates", the G3 plan's deferral table) are per area or per G2 deferral, not per contract, so the pending gate is a row of a new small table at the end of contract section 13. It has not run.

## Test double behavior

- Every simulated Git call is recorded as a process with `argv[0]` the Linux pin's path, a process identifier from 1000 on, and the environment names of the built environment: `PATH`, `HOME`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL`, `GIT_TERMINAL_PROMPT`, `GIT_CONFIG_COUNT`, and one key and value pair per command-scope setting (seven settings, eight with the credential's header).
- A remote operation (the `ls-remote` of a prepare, a remote head read, and a push) counts as a remote call, so the existing credential case keeps its counts.
- A push reads the remote first and refuses before starting a push process, so only a successful push starts one; a real adapter may also start a push that the lease refuses, which the cases allow.

## Risks

- The suite now assumes the Git CLI's push options and environment names in two cases; an adapter on another Git implementation would need the suite changed, which D3 (a) excludes for G3.
- `encodeHeadSnapshot` buffers the whole archive in memory; a large tree's snapshot needs a streaming variant later.
- The macOS process group of the reclaim program can be reused by an unrelated group after it ends; 16e decides the proof's details on macOS.

## Context

25b added `make native-acceptance`, whose Linux entry runs eight proofs (`linux_entry` in `scripts/native-acceptance.sh`) in the worker image and in the test image of `make verify-linux-cgroup`, and ran it on Docker Desktop for arm64. D11 (a) of [docs/g2-plan.md](../../../docs/g2-plan.md) requires all four matrix entries, with any entry not established recorded as open in the closure ADR; its hosted-runner labels name no Linux x86_64 runner. The coordinator's brief of 2026-10-27 keeps a GitHub-hosted `ubuntu-24.04` runner check for the Linux x86_64 entry open, and 25c runs Linux x86_64 under Docker Desktop on the iMac. Neither observes a Linux host kernel. A native Ubuntu x86_64 host with Docker Engine is available to this worker.

## Decisions

1. **The host.** A native Ubuntu 26.04.1 LTS host, `x86_64`, kernel 7.0.0-38-generic, cgroup v2, Docker Engine 29.8.2 (not Docker Desktop), storage driver overlayfs. The worker image and the test image are the digest-pinned Ubuntu 24.04 base (`UBUNTU_BASE`, `Makefile:11`). Coordinator decision of 2026-10-27: run on this host and record it truthfully. It is not a GitHub-hosted `ubuntu-24.04` runner, so the hosted-runner Linux x86_64 check of the coordinator's brief of 2026-10-27 stays open; these results are additional evidence of a native kernel and cgroup v2 beyond `linuxkit`.
2. **The entry name.** The entry stays `linux-ubuntu-24.04-x86_64`, which `scripts/native-acceptance.ts:77` builds from the base image and the recorder validates against `MATRIX_ENTRIES` (`packages/testing/src/scenario-results.ts:25`, `:116`). The run is told apart by its recorded platform: `platform.os` ends in "on Ubuntu 26.04.1 LTS", and the kernel and host fields name this host; `acceptance.md` labels the run native-host evidence. Coordinator decision; no code changes.
3. **Scope.** The eight Linux proofs of the runner (service lifecycle, worker kill, the `verify-linux-cgroup` supervisor crashes and cancellation, the journal, cancellation, and connectivity suites in the test image, and worker disk loss), plus `make scenario-worker-namespace-confinement` on `x86_64`, which the 25a design ([harden-worker-container-seccomp](../archive/2026-10-26-harden-worker-container-seccomp/design.md), line 78) assigns to the x86_64 iMac; this run adds the same check on a native x86_64 Linux host. On Docker Engine without Desktop the seccomp profile is applied by the host's own kernel, which 25b could not observe.
4. **Rows that stay open.** The G2 item 24b crash windows and the duplicate delivery in a Linux composition stay open: `apps/control-plane/test/crash-windows.integration.test.ts:34-35` skips them off Darwin, and the archived [run-g2-crash-windows](../archive/2026-10-26-run-g2-crash-windows/design.md) decision 8 explains why: the composed worker on Linux needs a delegated cgroup and an execution account, which only the privileged `verify-linux-cgroup` container provides, and that container has no network to the services. The coordinator carries this to `close-g2` as a candidate deferral or follow-up. The other rows that depend on later gates stay open as in 25b.
5. **Build before seed.** The Linux entry does not build the checkout, and its test image mounts the host's `dist/` read-only, so `npm run build` runs before the run. 25c fixes this ordering in the runner; this change does not.
6. **Host condition.** `/tmp` is a 31 GiB `tmpfs` with `usrquota`, 85 % full with other projects' caches; a first `make verify` failed with "Unknown system error -122" (`EDQUOT`) while Node.js wrote coverage. Every run therefore sets `TMPDIR=/home/petar/.cache/taskelith-tmp`, on disk. Other projects' files are not deleted.
7. **Failures are reported, not fixed.** A proof that fails is recorded as failed and reported to the coordinator as a candidate defect. No proof is skipped or retried to obtain a pass, and no product, runner, or test code changes here.

## Risks and limitations

- The host runs Ubuntu 26.04.1 LTS, not 24.04; only the containers run the pinned 24.04 base. The hosted-runner Linux x86_64 check of the coordinator's brief of 2026-10-27 is not replaced.
- A Linux host with AppArmor or SELinux enforcing a profile on the containers is not claimed unless the run records it.
- The records name the commit that ran, not a clean tree; `verification.md` states the revision.

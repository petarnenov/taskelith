## Context

G2 work item 10 provides the primitives that later items use to rerun each failure scenario identically against real PostgreSQL and NATS. The scenarios come from the launch authorization contract (section 10), the supervisor identity contract (sections 4 and 9), and the worker journal contract (section 13); decision D8 (a) runs the services through Compose from `make`, with a Toxiproxy container for partitions. G1 left identifier and clock generation to module-owned ports ([add-shared-kernel](/openspec/changes/archive/2026-10-24-add-shared-kernel/design.md) decision 1), and the SDLC module owns the `Clock` port of task admission.

Goals: deterministic time, identifiers, and randomness; named crash points with a crash at a chosen occurrence; kill and pause of process groups; partition and heal of a TCP route; the rule that product code does not depend on any of it.

Non-goals: the crash points themselves (each item that adds an outbox, inbox, journal, or launch path names its own), the deadline clock adapter that reads `CLOCK_BOOTTIME` or `mach_continuous_time` (item 15 qualifies it), power-loss simulation by a filesystem that discards unsynced writes (worker journal contract section 13 asks for it "where the harness supports it"; not in this item), latency or bandwidth toxics, and a scenario runner.

## Decisions

1. **A separate private package, `@taskelith/testing`.** The harness lives in `packages/testing`, next to the kernel, and follows the workspace package contract. Its tests and every other package's tests import it by name. The boundary check adds one rule: a file under `src/` of a package or application, other than the harness itself, does not import `@taskelith/testing`; tests and scripts do. The alternative, a `test/` helper directory per package, would copy the primitives into every package, and a module or adapter location would put test code on a production path.
2. **Ports stay with the modules; the harness satisfies them structurally.** The shared kernel reads no clock or random source and holds no ports (`shared-kernel`, Small kernel), and G1 decided that each module declares the generation port its use case needs. Moving `Clock` into the kernel would reverse that decision for no present caller. The harness therefore exposes plain shapes that TypeScript matches structurally: `WallClock` (`now(): Instant`) is the SDLC module's `Clock`, and a test proves the assignment; `MonotonicClock` (`readMilliseconds(): number`) and `IdSource<Kind>` (`next(): Identifier<Kind>`) are the shapes that items 14, 15, 17, and 20 can give their ports. The harness depends on the kernel only, and on the SDLC module only in its tests.
3. **One simulated machine, three clocks.** `SimulatedHost` starts at a given `Instant` and holds a wall clock, a deadline clock, and an uptime clock, all advanced only by the test. `elapse` advances all three. `suspend` advances the wall and deadline clocks but not the uptime clock, as Linux `CLOCK_BOOTTIME` and `CLOCK_MONOTONIC` behave across a suspend (launch authorization contract section 7), so a test can show that a deadline on the uptime clock is unsafe. `shiftWallClock` steps only the wall clock, in either direction, for a wrong or stepped wall clock beyond `skew`. Monotonic readings start at zero and do not survive a restart, so a scenario that restarts a machine creates a new `SimulatedHost`. Durations are non-negative safe integers of milliseconds; `ttl` and `skew` are whole seconds.
4. **Recorded seeds.** `SeededRandom` is Mulberry32 over a 32-bit seed: small, without a dependency, and reproducible in every Node version. `seedFromEnvironment` returns `TASKELITH_TEST_SEED` when set, so a failed run reruns with its seed, and a fresh seed from `crypto.randomInt` otherwise. A scenario records the seed with `t.diagnostic(rerunHint(seed))`, which the spec reporter prints in `make verify` output. Seeded identifiers are version 4 UUIDs drawn from the generator; sequential identifiers (`execution-1`, `execution-2`, ...) serve assertions that name identifiers. Both go through `parseIdentifier`, so an identifier the kernel rejects fails the test at once.
5. **Crash points are names, not hooks.** A crash point is a contract's name, optionally on one side of a commit: `CP8`, `W1.before`, `W5s.after`. The code under test calls `reach(name)` on the crash point port of its own module, whose production adapter does nothing; `CrashPoints` is the harness adapter. It records every point reached, in order, so a test can assert the write order, and crashes at the armed occurrence of one point: by throwing `SimulatedCrash` in process, for adapter tests, or by `SIGKILL` of its own process, for a child armed through `TASKELITH_CRASH_POINT=<point>[@<occurrence>]`. `SIGKILL` gives no chance to flush or clean up, as a crash does. The occurrence covers points reached once per message, such as W1.
6. **Process groups for kills and pauses.** `ScenarioProcess` spawns a child as the leader of a new process group and signals the group, so that a supervisor's descendants receive the same kill, `SIGSTOP`, or `SIGCONT`. Pausing models a supervisor "paused before spawning, then resumed" (supervisor identity contract section 9); a suspended machine is `SimulatedHost.suspend`. It keeps stdout and stderr, and `waitForOutput` synchronizes on a line the child prints, rather than on a delay. It targets Linux and macOS, the worker matrix's operating systems.
7. **Toxiproxy through `fetch`, with configured routes.** The server starts with two routes from `infra/services/toxiproxy-routes.json`, `postgres` and `nats`, whose listen ports Compose publishes on ephemeral localhost ports, so a test needs no port allocation and `scripts/services.sh` exports their URLs next to the direct ones. The Compose change adds only the new service, so that it merges with parallel edits of the other services. The client covers what the scenarios need: address a route by name, `disconnect` (disable it: open connections close and new ones are refused), `blackhole` (a `timeout` toxic with `timeout: 0` on both streams: connections stay open and data is dropped), `heal` (remove every toxic and enable), and `reset` of the server between scenarios; creating routes at run time is left out until a scenario needs a route the configuration lacks. The checks in [docs/g2-infrastructure.md](/docs/g2-infrastructure.md) section 7 marked the API unverified; this change verifies it against the pinned image. The API has no authentication, so the Compose project publishes it only on the loopback interface, as item 9 publishes PostgreSQL and NATS.
8. **Real services, no fakes.** The harness provides no broker, database, or timer fake. The partition test reaches the real PostgreSQL through `pg` and the real NATS through its INFO greeting, both through Toxiproxy, and observes the failure and the recovery: a disconnected route refuses or closes connections, a black-holed one leaves an open session without an answer, and a healed one serves new sessions.

## Risks / Trade-offs

- [Coverage of child processes] The `SIGKILL` path runs in a child, which the coverage of the test process does not measure. → The child's behavior is asserted from its exit signal and output; the in-process path covers the same code.
- [Signal timing] A stopped state appears asynchronously. → Tests poll the process state with `ps` for at most one second instead of sleeping a fixed time.
- [Seed space] 32 bits can repeat across many runs. → Seeds identify reruns, not security; collisions only rerun a scenario that already passed.

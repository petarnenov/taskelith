## Context

G3 item 43 (`docs/g3-plan.md`, row 43) asks for the G2 native acceptance rows that ADR 0015 decision 5 ("Containment and platforms", "Cancellation race g and the 24c-dependent rows on macOS and Linux") defers to G3. `complete-g2-native-acceptance-rows` ran the Linux x86_64 parts on the native Linux host through the worker's Linux cgroup supervisor. This change takes the `macos-26-x86_64` parts, as the brief scoped them: the system-level cancellation part and the connectivity part of the Cancellation and Connectivity (G2) rows, run through the worker's macOS supervisor instead of the test-side process-group launch host, and cancellation race g. The host is the coordinator's 2020 Intel iMac (macOS 26, x86_64). `macos-26-arm64` with its process ownership re-run, `linux-ubuntu-24.04-arm64`, and the hosted `ubuntu-24.04` re-dispatch stay open under item 43.

Before this change the scenario files skipped outside Linux (`test/g2-scenarios/scenario-run.ts:16` at `f6696995`): their workers composed `processGroupHost` or, under the privileged Linux runner, the cgroup supervisor, and the process-group host and the leftover process listing read `/proc`. The skip came from the coordinator's integration `make verify` on macOS, which hung on these files (ADR 0015, "Partition, cancellation races, stale generations"). Race g was a stub skipped as not applicable on Linux.

## Decisions

1. **Opt-in switch, `make verify` unchanged.** `TASKELITH_MACOS_SCENARIOS=1` on macOS selects the worker's own macOS supervisor (`macosLaunchFromEnvironment`, `test/g2-scenarios/scenario-launch.ts`); set off macOS it throws when the file loads, so a misconfigured run never falls back. Without it `make verify` on macOS keeps skipping the files, as `make verify` hung on them before and needs no extra Docker time on the shared macOS hosts. The three launch hosts are one type, `ScenarioLaunchHost` (`cgroup-supervisor`, `macos-supervisor`, `process-group`), chosen once in `SCENARIO_LAUNCH_HOST`; the Linux switch is unchanged.
2. **The product launch host on macOS.** Under the macOS switch `ScenarioWorker` composes `supervisionHost` without a containment parent, which `hostPlatform` turns into the macOS platform with the native readers, wrapped in `HeldStart` for race c's held start, as on Linux; `cgroupHost` becomes `workerLaunchHost`, since it composes whichever supervisor the platform gives. The worker reports host platform `darwin`, uses the worker's own admission check (`linuxContainmentCheck`, which `apps/worker/src/main.ts` composes on every host and whose scope does not apply on macOS) and the real volume probe of the APFS data root; the Linux stub probe stays for tmpfs test volumes. The crash-before-ack fixture builds a `ScenarioWorker` from the inherited environment, so it switches with it.
3. **Leftover processes on macOS.** macOS has no `/proc`, so `processesNaming` reads `ps -axww -o pid=,args=` there (`parsePsListing`, unit-tested); Linux keeps `/proc`. Each match still needs the scenario's directory in its command line.
4. **Guard and cancel signal.** `assertContained` becomes `assertWorkerSupervised`: under the cgroup supervisor it checks the containment as before; under the macOS supervisor each scripted process's parent (`ps -o ppid=`) must be a supervisor process (`SUPERVISOR_MAIN`) naming that worker's data root, so a test-side supervisor or another worker's supervisor fails it. The macOS first supervisor sends the group `SIGTERM` and then, after the grace, a kill (`worker-supervisor` "Cancellation of the process set"), and the scripted Node process ends on `SIGTERM`, so `CANCEL_SIGNAL` is `SIGTERM` there, as on the process-group host.
5. **Race g.** With a held run, the scenario waits for the start, checks the guard, holds the worker's next supervisor recovery (`aroundSupervisorRecover`, a test-side wrap of `ExecutionSupervision.recover`, which starts the adopter), and once the liveness check waits in it kills the launching supervisor alone with `SIGKILL` (the child, in its own process group, keeps running). As the seed chooses, it commits the cancel while the hold keeps any adopter from starting and then releases the hold, or releases it first and cancels once the recovery has adopted the child and one adopting supervisor runs. The worker's liveness check finds the supervisor dead and the child alive and starts an adopting supervisor (supervisor identity contract section 6, "Adopt the child"). The scenario checks that the control plane records `cancellation-not-applied` on the execution while the child still runs with the same process ID. Released, the child exits; the next recovery finds no live supervisor, no exit, and the child gone, and reports `uncertain` (section 6, "descendants may live, and no containment proves they do not"); the scenario checks that the execution stays `started` with the evidence `cancellation-not-applied` then `uncertain`, and that the task result stays `pending`, as section 8 says ("the execution stays `started` for reconciliation"). On every other launch host race g stays skipped as not applicable.
6. **Target and proofs.** `make verify-macos-g2-scenarios` builds the checkout and runs the files with the variable through `scripts/services.sh run` against its own services project, the composition the macOS harness proofs already use; `FILES` and `PATTERN` select, and off macOS it fails with status 2. The macOS entry of `make native-acceptance` runs `acceptance-cancellation-races` and `acceptance-partition` through it, under the same scenario names as the Linux entry, which its entry field tells apart.
7. **Evidence on this host only.** Two `make native-acceptance ENTRIES=macos` runs with the seeds `20261026` and `7`, those of 24c's and the Linux part's evidence, each under the host-wide Docker slot (`scripts/docker-slot.ts run`), so that no `make test` of another session shared Docker during them.

## Risks

- A macOS run of `make native-acceptance` takes about five minutes longer.
- The guard covers races c, g, and h only; the other scenarios rely on the same host composition.
- Race g relies on the worker's liveness check finding the killed supervisor; its waits are 30 s and 60 s, wide for the loaded iMac.

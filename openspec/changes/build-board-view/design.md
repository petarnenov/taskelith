# Design: build-board-view

## Context

G3 item 29 (`docs/g3-plan.md`, row 29) builds the project board and the task detail on the shell of item 28 (`build-web-spa-shell`, `serve-web-spa-from-control-plane`). The server side is in `dev`: `listProjects` (11a), `streamProjectEvents` (14), `readBoard` with the `card-changed` and `board-changed` events (15a, 15b). The [product ports contract](/docs/contracts/product-ports.md) sections 3.1 to 3.9 define the columns, the framework mapping, the card, the merge gate, the board states, and the session activity; the [control-plane wire contracts](/docs/contracts/control-plane-wire-contracts.md) sections 8 and 10 define the snapshots and the event streams.

**Goals.** The board of the chosen project, every board state of the product UI requirement "Board states", the header's project picker, live updates through the event stream with its cursor and resync, and the 28b follow-up that routes a 401 `unauthenticated` answer into the session state.

**Non-goals.** The task detail (29b), new OpenAPI operations or contract changes, project setup screens, the inbox and its count (item 32), new task (item 30), the agent session screen (item 31), and the audited reconciliation action of an uncertain process.

## Decisions

1. **A board port and its adapter.** `src/board/board.ts` is the port: `BoardGateway` with `listProjects`, `readBoard`, and `openEvents`, results as `ReadResult` (`read`, `unauthenticated`, `denied` with the role a 403 names, `not-found`, `unavailable`), and stream events as `BoardStreamEvent`. `createBoardGateway` (`control-plane-board.ts`) is the adapter over the 28a typed fetch and the browser's `EventSource`, which tests replace through `openEventSource`. Every board operation is a GET, so no request carries a CSRF token. The view types are the generated OpenAPI types; no shape is copied.
2. **Bodies checked for the fields the board shows.** The typed fetch checks no body, so `board-wire.ts` checks every field the board renders, each enum against the label record of `board-labels.ts`, positions against `EventPosition`, and instants for a readable time. A body that fails reads as `unavailable`, like 28b's session bodies. A test keeps every label record's keys equal to its OpenAPI enum, so a new value in the document fails the test instead of rendering a blank label. A 401 counts as `unauthenticated` only with that reason in its details.
3. **Every page of projects.** `listProjects` is paged (`ProjectPage.next`); the adapter follows `next` until it is absent and reads a page whose `next` names a cursor it already followed as `unavailable`, and reads a `next` beyond `MAX_PROJECT_PAGES` (100) pages as `unavailable` too, so a broken server cannot loop it through one cursor, a cycle of them, or ever new ones.
4. **The feed: snapshot, then stream.** `startBoardFeed` (`board-feed.ts`) reads the board and opens the stream with `after` set to the snapshot's `position`; the browser sends `Last-Event-ID` itself when it reconnects, and that header wins over `after` (wire contracts section 10). It applies a `card-changed` event by replacing or adding the card with its `runId` and a `board-changed` event by setting `workersOnline`, each only when its position is above the view's, compared as `BigInt` because a 16-digit position exceeds a safe number; a skipped event shows no new state.
5. **Re-reads.** On `resync` the feed closes the stream, which would otherwise reconnect into the same `resync`, reads the board, and opens a new stream after the new position: at once for the first resync, and for each further resync before the stream delivered a change after `RESYNC_DELAY_MILLISECONDS` (1 s), doubled each time up to `STREAM_RETRY_MILLISECONDS`, so that a cursor that keeps expiring or an event that stays unreadable cannot loop reads and streams; a delivered change resets the delay, and stopping the feed cancels it. On `stream-ended` it reads the board, so that `callerMayAct` follows the new roles, and leaves the stream to the browser's reconnect with `Last-Event-ID`; a reconnect refused with 403 closes the stream for good. An event the adapter cannot read becomes a `resync`. A stream that closed for good (an `error` with `readyState` `CLOSED`, as after an error status, which `EventSource` never shows) is closed, the board is read again, which reveals a 401, 403, 404, or 503, and a new stream opens only after `STREAM_RETRY_MILLISECONDS` (10 s) on the injected `Clock`, so a stream that keeps failing is not reopened in a loop. Changes that arrive while a read runs are kept and applied over its snapshot, which skips those it already holds; only the latest read's answer counts. Changes are kept only while a read runs, so a long healthy stream keeps none, and a read that falls `MAX_CHANGES_DURING_READ` (1,000) changes behind the stream is replaced by a resync, which bounds them during a stalled read. A failed read closes the stream and drops the view, so the board shows no data that may be wrong.
6. **Liveness and the last known state.** The feed reports `connecting` until the first stream opens, `live` while it is open, and `lost` from an `error` or a `resync` until a stream opens again, also while the re-read runs and a new stream connects. While `lost`, the board keeps its cards and names the time of its last known state, the later of the snapshot's `asOf` and the `occurredAt` of the events applied since, in a `time` element with the instant as `dateTime`.
7. **Board states.** `BoardPage` shows, in order: projects loading; projects unreadable (an error with a retry); no project, the first run; then the chosen project's board: loading, a failure (unreachable, no access for 403, which names the role from `details.requiredRole` when the answer has one, unknown project for 404, and an ended session for a 401 that a newer session view leaves on the board, decision 12, each with a retry and without columns or cards), or the board with notices for lost live updates, no workers online (`workersOnline` 0), and read-only (`callerMayAct` false), and a line for an empty board above its empty columns. Each loading state is a status line that names what loads, beside a Mantine `Loader` that is left out under `prefers-reduced-motion: reduce` (`useReducedMotion`), because the theme's `respectReducedMotion` does not stop its animation. The first-run Alert (decision Q3) says that the project setup screen is not built yet, that an installation-owner creates a project through `createProject` (`POST /projects`) and assigns its members, and that the `taskelith` CLI has no project command (`src/cli.ts` on `dev` knows only `plan`, `--version`, and `--help`); `listProjects` lists only the projects the caller holds a role on, so the notice also covers a caller without one. It has no link.
8. **Columns and the merge gate.** The columns follow `BOARD_COLUMNS` under the short labels of product ports section 3.1, each with its lifecycle stage name as a dimmed line and its card count. Accept and integrate is not a column: a narrower section between Review and Archived lists the Review cards whose merge gate state is not `not-ready` with that state, because a card at its Close stage stays in Review until it merges (product ports section 3.2, rule 6). Each card also shows its merge gate state unless it is `not-ready`. The columns scroll sideways in a Mantine `ScrollArea`, the deliberate board columns that the "Design rules" phone-width scenario allows. Its viewport, which Mantine leaves unfocusable, gets `tabIndex` 0 and is a region named "Board columns" through `viewportProps`, so a keyboard reaches and scrolls the later columns in browsers that do not focus scroll containers themselves, such as Safari.
9. **The card.** A Mantine `Card` as an `article` named by its title: work type and framework version, "Step:" with the native stage identifier or "platform-managed" (product ports section 3.2) and the stage state, the gate as a dot `Badge`, "Waits for" the `CardWait`, the obstacle ("Not placed" or "Rejected", the reason in words, the retry number, the source, and `observedAt`), the task end, the session indicator, the merge gate state, and the count of open inbox items. The card is not interactive in this change.
10. **Session indicator.** `SessionIndicator` shows a Mantine `Loader` while the session works and a still `ColorSwatch` otherwise: indigo while it waits or its worker is unreachable, gray (muted) when it stopped or there is none, and red (danger) when the process state is uncertain, each beside a label that names the state, with the last contact time of an unreachable worker. Under `prefers-reduced-motion: reduce` (`useReducedMotion`) a working session gets the still indigo swatch and keeps its label. The swatch and the loader are `aria-hidden`; the label carries the meaning.
11. **Project picker.** `ProjectsProvider`, inside `AppLayout`, so only an authenticated session lists projects, holds the listing and the choice; the choice is kept in `localStorage` under `taskelith-project` inside `try` and `catch`, so blocked storage only forgets it, and a kept project that is no longer listed falls back to the first. `ProjectPicker` is a Mantine `Menu` behind a default `Button` that reads "Project: <name>" with the name truncated; it shows in the header from `sm` and in the navbar below it, where the header has no room at 320 px (28b decision 5). The menu marks the chosen project with the check icon and `aria-current`. With no project it renders nothing.
12. **401 routing.** `SessionProvider` gains `expiryOfRequest`, which a request calls as it starts and which returns the function that ends the session it started under: from a signed-in view that function shows the sign-in page with the notice `expired`, then reads the session again as after a logout, which keeps the token of the next anonymous session and takes over a session that another tab logged in. It does nothing once a newer session view showed since the request started, so a late 401 of a request sent before a logout cannot end the session of a later login, even after the board that sent it unmounted. `useBoardServices` wraps the gateway so that every `unauthenticated` result calls the expiry of its request, and a gateway that throws reads as `unavailable`. The stream cannot see a status, so a refused stream reaches the expiry through the re-read of decision 5.
13. **Task detail route.** `TASK_DETAIL` in `src/screens.ts` routes `/projects/:projectId/cards/:runId` to the empty `PlannedPage`, which names change `build-task-detail`; it is not in the navigation, and no card links to it, so no link leads to an unbuilt screen (decisions Q2 and Q3). Change 29b replaces it with the board and a Mantine `Drawer`. `PLANNED_SCREENS` lists the screens that still show the planned page; the board's route is now `BoardPage`.
14. **Contrast pairs.** The test adds the gray alert's title and message, text and dimmed text on a card (white in the light scheme, `dark.6` in the dark one, Mantine's `Card` stylesheet), and the dot badge's text (black on white, white on `dark.5`, its stylesheet). Every other pair the board draws is already tested: default and light variants, the indigo and red alerts, dimmed text and menu items on a dropdown. The picker's label is not dimmed, because dimmed text on a hovered default button in the dark scheme is 3.93:1.
15. **Test environment.** jsdom has no `ResizeObserver`, which Mantine's `ScrollArea` creates; `test/setup.ts` adds an inert one beside its `matchMedia` stub.

## Proof of concept

The change follows `docs/ui-poc/src/screens/Board.tsx` (columns, card), `States.tsx` (board states), `LiveStatus.tsx`, `board-model.ts`, `docs/ui-poc/src/ui.tsx` (`SessionBadge`, `GATE`), and the project button of `docs/ui-poc/src/main.tsx`. Departures, each required by a requirement or decision ("Reference proof of concept"):

- **No demonstration flows.** POC: `useBoardFlow` of `Board.tsx` simulates merges, stops, reconciliation, and toasts on timers. No mock data (item 28 decision); the board shows only what `readBoard` and its events answer, and no action of those flows has an operation in this change.
- **No swimlanes, auto-merge button, "need you" count, "sessions live" badge, or New task button on the board.** POC: the `PageHeader` aside and `SegmentedControl` of `Board.tsx`. The auto-merge setting and its drawer belong to settings (item 34), the inbox count to item 32, and swimlanes by harness need session data the board does not read; New task stays in the header (28b).
- **Merge gate as a section, not a lane of steps.** POC: `MergeProgress` of `Board.tsx` draws merge steps and conflict files from fixtures. The board has only the `MergeGateState` (product ports section 3.4), so the gate lists the cards with their state.
- **States from the board, not a state switcher.** POC: `States.tsx` previews every state with a `SegmentedControl` and skeleton cards, and its first run is a five-step `Stepper` with action buttons. The board shows each state when its data says so; the first run is one Alert without links, because no setup screen is built (decision Q3), and the restore quarantine state has no field in `Board`.
- **Live status as a notice.** POC: `LiveStatus.tsx` shows a "Live · cursor" badge with a tooltip. The board says nothing while live and shows an Alert with the last known time while lost (product UI "Live updates lost").
- **Colors.** POC: orange for waiting, blocked, stale, and the no-workers banner, teal for passed and live. Mantine's orange light alert title is 3.62:1 in the light scheme, so the notices are indigo and gray; gate and session colors are only dots and swatches beside text that names the state.
- **Indicator.** POC: `SessionBadge` draws a `Badge` with a `Loader` or a dot. The board draws a `Loader` or a `ColorSwatch` beside plain text, so the label keeps the page's text contrast, and adds reduced motion.
- **Project picker.** POC: a static "Project taskelith" button. It is a `Menu` of the listed projects, and moves into the navbar below `sm`.

## Risks and trade-offs

- A stream that closes for good is opened again only after 10 s, so the board may show the lost notice that long after the control plane recovers; a first resync reopens at once, and a repeated one waits up to 10 s.
- After `stream-ended` the browser reconnects on its own schedule, so the lost notice may show for its reconnect delay.
- The kept project is a browser convenience, not an address: a link to the board does not name a project. Change 29b's task-detail route carries the project in its path.
- The board reads all projects on every authenticated page because the picker sits in the header; a large installation with many pages of projects pays that on each sign-in.
- `formatInstant` uses the browser's locale and time zone, so a screenshot or report shows local times.
- The audited reconciliation of an uncertain process (product UI "Session activity indicator", scenario "Process state uncertain") is not offered: the card shows the state in the danger color, and the action belongs to the inbox (product ports section 4.1, items 15b and 32).

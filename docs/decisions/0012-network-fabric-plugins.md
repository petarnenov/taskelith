# ADR 0012: Network fabric plugins — local default, Headscale, hosted Tailscale

Date: 2026-10-25
Status: Decided by the owner on 2026-10-25 in the project conversation. Recorded; no network fabric port, plugin, or integration of network fabric with enrollment exists yet. Each decision is implemented in the gate named below.

## Context

- The owner asked for an analysis of integrating Tailscale so that Taskelith can work with machines registered in a Tailscale network, then decided the outcome: connectivity to machines is a plugin/adapter capability; a plain local network is the default without Tailscale-like capabilities; a self-hosted Headscale adapter comes next; the hosted Tailscale control plane comes last.
- Tailscale has two halves. The client, `tailscaled`, is open source (BSD-3-Clause, [tailscale/tailscale](https://github.com/tailscale/tailscale/tree/v1.104.2), release v1.104.2 observed 2026-10-25). The coordination server keeps the device registry, distributes keys, applies ACLs, and assists NAT traversal; on the hosted service it is closed ([Tailscale: open source at Tailscale](https://tailscale.com/opensource), unversioned page retrieved 2026-10-25). Headscale ([juanfont/headscale](https://github.com/juanfont/headscale/tree/v0.29.6), BSD-3-Clause, release v0.29.6 observed 2026-10-25) is an independent open-source implementation of that coordination server, self-hosted.
- [Architecture section 13](../architecture.md#fresh-installation-and-deployment) already requires workers to initiate outbound connections only, with no public inbound listeners, so a mesh overlay fits the worker connectivity model without changes to the protocol.
- The [technology policy](../architecture.md#established-open-source-technology-policy) requires established open source and no mandatory proprietary SaaS. A closed hosted service is admissible only as a plugin by an explicit owner decision, as [ADR 0006](0006-github-first-scm.md) did for GitHub.com.
- [ADR 0003](0003-first-integrations-and-plugin-kernel.md) decision 8 and [ADR 0008](0008-product-ui-and-integration-authority.md) decision 6 route new capabilities through microkernel ports as plugins or adapters, and define a port contract in the gate that first implements it.
- `tsnet` ([docs](https://tailscale.com/docs/features/tsnet), unversioned page retrieved 2026-10-25) embeds Tailscale into Go programs. Using it from the TypeScript product would need a Go bridge, which [ADR 0004](0004-first-class-engineering-principles.md) and the architecture forbid.

## Decisions

1. **Network fabric is a plugin kind.** Connectivity to worker machines sits behind a vendor-neutral port (working name `NetworkFabricProvider`), with each fabric delivered as a separately versioned plugin under ADR 0003 decision 8 and ADR 0004 principle 4. No kernel, module, contract, or test names a specific fabric. The port contract is defined by the first bounded change that adopts it, following ADR 0008 decision 6. Enrollment already exists from G2 ([G2 plan](../g2-plan.md), item 13); this decision does not modify it and does not make the port a condition of it.
2. **Local networking is the default.** The default plugin addresses machines by operator-supplied hostnames or addresses at enrollment, with no mesh, NAT-traversal, or provisioning capability. The port is capability-gated so that the local plugin implements only the base behavior; every Tailscale-like capability (node provisioning, inventory, revocation, DNS names) is an optional capability declared in a plugin manifest and never assumed by the core.
3. **Headscale is the first mesh plugin.** A self-hosted Headscale control server (open source, BSD-3-Clause) is the preferred Tailscale-protocol fabric, because it keeps an installation free of a mandatory closed provider. Its qualification covers version-specific maintenance, adoption, security reporting, and operational evidence per the dependency policy; scale evidence for the 1000-machine stage is a named gate.
4. **The hosted Tailscale control plane is admitted last, as an optional closed-hosted plugin.** The owner admits the closed hosted Tailscale coordination service as an optional plugin, under the rule of ADR 0006: its terms of service, data handling, API version, maintenance, and security evidence are recorded before admission. A Taskelith installation is never required to use it, and the local and Headscale plugins remain fully supported alternatives. Automation uses the Tailscale API with OAuth client credentials ([docs](https://tailscale.com/docs/features/oauth-clients), unversioned page retrieved 2026-10-25).
5. **The Tailscale client is infrastructure, not product code.** Where an installation uses a Tailscale-protocol fabric, `tailscaled` runs as a prebuilt third-party service on the machine, like NATS, and not as product-owned code. `tsnet` embedding is rejected because it would require a Go bridge. Worker-side enrollment may invoke the pinned Tailscale CLI as an explicitly operator-approved host mutation.
6. **Fabric identity is an observation, never an authority.** A fabric node identity may be recorded as an observation bound to a `workerId`. It never replaces application enrollment, per-worker broker credentials, or launch authorization, and fabric reachability never decides execution lifecycle facts (invariants 4 and 13, findings F01 and F02).

## Consequences

- The dependency register lists the three plugins' external components as `candidate` until version-specific qualification: the Headscale server, the hosted Tailscale API, and the pinned Tailscale client.
- Implementation order follows the plugin order: the local plugin in the first bounded change that adopts the port, Headscale toward the G6 pilot, hosted Tailscale last.
- This ADR implements nothing by itself. Each plugin becomes work items in its gate's plan, tracked through the selected SDLC framework.
- A deployment that never enables a mesh plugin keeps the base functionality; mesh capabilities stay unavailable.

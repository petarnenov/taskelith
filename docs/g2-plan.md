# G2 work plan

Date: 2026-10-24. Status: proposed plan. G2 has not started and no G2 item is authorized. The owner starts G2 only after G1 closes (G1 item 14, `close-g1`) and decides the open decisions below that block the first items. The owner's G1 authorization to merge each reviewed task and start the next one without a separate approval was given for G1; whether it extends to G2 is decision D14. No G2 product code exists yet.

G2, "Durable execution vertical slice", is defined in [architecture section 13](architecture.md#delivery-sequence): PostgreSQL state and outbox, NATS transport, enrollment and authorization boundaries, a local worker journal, a supervisor, and a deterministic test harness; the real worker protocol run even on one host; a minimal local installation composition, the `EvidenceStore`, launch authorization, and resource admission. Its exit evidence: submit an admitted task, assign it, execute it, and persist its result, and exercise duplicate delivery, process-launch crash windows, partition, cancellation races, stale generations, and disk loss. Section 13 requires each gate to be decomposed through the SDLC framework into reviewed, independently verifiable work items; this plan lists them. Each item is one OpenSpec change, developed in its own git worktree and merged into `dev`.

## Starting point

- G1 delivered the private workspace packages `@taskelith/kernel` (opaque identifiers, failure vocabulary, typed results, instants, event metadata), `@taskelith/sdlc` in `packages/modules/sdlc` (workflow model, gates with compare-and-set generations, task admission with the `TaskAdmissionService`, `AdmissionRepository` and `Clock` ports and an in-memory repository, the `SdlcFramework` port and its conformance suite), `@taskelith/plugin-sdk` (manifest schema and library-level registration), and `@taskelith/contracts` (`sdlc.asyncapi.json` and `sdlc.openapi.json`, generated types and validators, and the breaking-change check in `make verify`). The specifications are the `sdlc-*`, `shared-kernel`, `plugin-registration`, `contract-tooling`, and `workspace-packages` capabilities in `openspec/specs/`.
- On this plan's date, G1 items 11 (`implement-openspec-framework-adapter`), 12 (`freeze-sdlc-framework-port`), and 14 (`close-g1`) are still open. G2 builds on the frozen port and on the closure ADR that item 14 writes, including its list of the pre-G2 contracts.
- G1 item 7 deferred the ownership generation of an admission to G2, and G1 decision D4 (a) deferred the attempt and assignment state machines to G2.
- [ADR 0007](decisions/0007-g0-closure.md) deferred two items to G2: implementing the data namespace of the [storage contract](storage.md) (identity and ownership checks, root locks, atomic persistence, crash consistency, credential storage), and starting native acceptance of the [worker matrix](worker-platforms.md), including qualification of the harnesses on Linux inside the worker image.
- [Architecture section 15](architecture.md#15-decisions-still-requiring-evidence-or-owner-scope-confirmation) requires launch linearization and expiry, supervisor identity and adoption, local journal durability, and capacity reservations to become reviewed protocol contracts before G2 execution code. The fifth pre-G2 contract, both-framework mapping feasibility, is G1's work (items 10 and 12) and is confirmed by `close-g1`.
- The [trust contract](trust-model.md) and the [operational targets](operational-targets.md) fix the identities, enrollment, credential generations, launch authorization TTL and skew (`30s`/`5s`), resource budgets, journal backlog limits, disk floor, and broker retention that G2 implements and tests.
- `apps/` is not yet a workspace; the root manifest lists only `packages/` paths. `make verify` already needs Docker for the OpenAPI breaking-change check.
- PostgreSQL, NATS JetStream, and every runtime client library remain `candidate` in the [dependency register](dependencies.md), with no version or image selected.

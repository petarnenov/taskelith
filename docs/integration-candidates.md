# First integration candidates

Assessment date: 2026-10-24. Status: evidence base for the owner's integration decisions in [ADR 0003](decisions/0003-first-integrations-and-plugin-kernel.md). The owner selected Claude Code (G3), OpenAI Codex CLI (G4), Antigravity CLI (`agy`), and OpenCode, in that order. For the SCM, the owner first selected Forgejo, then GitHub.com as the first SCM and Forgejo as a later second SCM ([ADR 0006](decisions/0006-github-first-scm.md)). Nothing here admits, installs, or contacts an integration. Every component stays `candidate` in the [dependency register](dependencies.md) until version-specific qualification passes.

Sources: a link labeled "docs" is an unversioned page retrieved on 2026-10-24. Every other external source is pinned to a tag, a commit, or an exact package version. Claims without a source are marked unverified.

## Criteria

A candidate that fails one of these is ineligible.

### Preferences

These rank eligible candidates. Failing one does not make a candidate ineligible.

- A stable, vendor-supported programmatic interface rather than an experimental one ([architecture section 2](architecture.md#established-open-source-technology-policy) prefers stable releases over pre-release APIs on critical paths).
- An official TypeScript SDK.
- A provider path that a harness plugin can authenticate with a subscription; since [ADR 0005](decisions/0005-harness-subscription-account-pools.md), harness authentication is subscription-only, so account-free or API-billed endpoints are not a goal. ADR 0005 decision 2, as amended on 2026-10-27, puts the user's own API key first for Claude Code.
- A private security reporting channel rather than public issues only.
- SCM: an LTS line (ADR 0003 decision 3) and built-in CI.
- SCM adapter criteria proposed by this assessment, not by the architecture: repository-scoped API credentials, pull request and review APIs, HMAC-signed webhooks, a commit-status API, and server-enforced merge blocking on required statuses and reviews. They are a proposed way to meet the G3 review and verification evidence.

Consequences for the plugins:

- The `agy` plugin must not advertise externally answered approvals or turn-level interruption until they are native. In headless mode a tool that needs approval is soft-denied. Pre-set policy alone is not accepted (ADR 0003 decision 11), so `agy` qualification must find an external approval mechanism comparable to Claude Code's or Codex's; candidates to examine include PreToolUse hook decisions ([CHANGELOG#L899](https://github.com/google-antigravity/antigravity-cli/blob/1.4.7/CHANGELOG.md#L899)) and the alpha `google-antigravity` Python SDK ([PyPI](https://pypi.org/project/google-antigravity/0.1.22/)), both unverified for this use. This does not affect G3 or G4, whose harnesses have every capability `verified`.
- OpenCode allows most permissions by default and its server is unauthenticated unless a password is set ([permissions.mdx](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/web/src/content/docs/permissions.mdx#L168-L173), [server.mdx#L39](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/web/src/content/docs/server.mdx#L39)), so its adapter must force `ask` and set a password.
- Claude Code and `agy` are closed. Their license terms, provider dependency, and data-handling terms must be recorded before admission (ADR 0003 decision 2).

### Delivery sequence

- **G3: Claude Code.** It is the first real harness and has every mandatory capability `verified` (interruption at turn level); macOS x86_64 runs of the pinned SDK 0.3.308 (CLI 2.1.308, the CLI `stable` tag) confirmed them ([qualification record](qualification/claude-code.md)); the table above shows the latest releases observed earlier the same day. The capability contract and conformance suite are written for the agent port, not for Claude Code (ADR 0003 consequences).
- **G4: Codex.** It must be a different harness from G3. It differs in vendor, process model, and protocol: a JSON-RPC app-server rather than a CLI-spawning SDK with NDJSON. That makes it a real test that the port is not an abstraction around one SDK. Codex conformance runs before the port is frozen. Risk: the vendor calls app-server experimental and unsupported for production, so the G4 plugin pins an exact version and qualification re-runs on each upgrade. macOS x86_64 runs of the pinned 0.164.0 confirmed multi-turn, correlation, resume, external approvals, interruption (turn level), and outcomes, and observed analytics on by default ([qualification record](qualification/codex.md)).
- **After G4: `agy`, then OpenCode,** as additional plugins that add no kernel change.

## Qualification before admission

These tests use exact pinned versions on the qualified Linux and macOS targets:

- Network egress: with telemetry disabled by configuration, no telemetry traffic leaves the worker (ADR 0003 decision 4). Every other outbound destination is recorded for the plugin; until G8, documented non-telemetry vendor traffic is acceptable (ADR 0003 decision 10).
- Closed harnesses: recorded license terms, provider dependency, data-handling terms, version, maintenance, and security evidence (ADR 0003 decision 2).
- Harness conformance against the agent port: multi-turn, prompt correlation, resume after harness restart, permission request answered by an external client, interruption, exit status, and the state of pending approvals across a crash or connection loss. A capability the harness lacks is not advertised.
- Provider path: the configured provider or gateway, including Responses API support for a Codex gateway or local endpoint.
- SCM admission tests for the first SCM, GitHub.com (ADR 0006): recorded terms of service and data-handling terms; GitHub App permissions; installation tokens limited to the project's repositories and their expiry; denial of access to other repositories; a real repository task with independent review and verification evidence.
- SCM admission tests for Forgejo, when it is added: open-source self-hosted deployment on Linux; HTTPS and SSH with project-scoped credentials and denial of access to other repositories and admin endpoints; a real repository task with independent review and verification evidence; backup and restore; and upgrade to the next supported line.
- Proposed Forgejo adapter checks, from the proposed criteria in [Preferences](#preferences): pull request, review, commit status, protected-branch merge blocking, webhook signature and redelivery, and a TypeScript client generated from the pinned spec. A failed check is assessed and recorded, not an automatic rejection.
- Independent adoption, maintainer, and governance evidence for the chosen versions, recorded in the dependency register.
- Resource footprint on the reference host in [operational targets](operational-targets.md).
